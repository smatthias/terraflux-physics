# Weather snapshot timeline v1

The viewer accepts:

```json
{
  "schema_version": "terraflux.weather.timeline/v1",
  "frames": ["forecast or mobile-response object", "next frame object"]
}
```

The strings above are placeholders; each entry must be a complete forecast/v1 or mobile_response/v1 object validated by the existing viewer contract. Frames share an exact grid and UTC start time, and their elapsed_seconds strictly increase. A timeline contains 2–240 frames, subject to the viewer limits of 65,536 cells per frame and two million cell snapshots in total. File loading is limited to 20 MB.

A frame can carry precipitation only when it is a mobile response with an accumulation interval matching that frame. Missing precipitation does not mean zero rainfall. The bundled example includes cumulative rainfall at every positive-time frame. The time-zero frame has no accumulation layer and disables rainfall. The displayed interval endpoint and forecast valid time advance with the selected frame.

Playback selects stored frames every 700 ms and stops at the final frame. A fixed field range across the timeline preserves color/height comparability; missing values remain excluded from that range. Scrubbing and stepping pause playback. No interpolation, live solver, or coupled precipitation physics is implied; wind evolves only when the frames come from the coupled wind model below.

## Ocean circulation extension

A timeline written by `terraflux-run-ocean-circulation` carries `terrain` (the basin: continents above sea level) and an `ocean` member (schema `terraflux.ocean.circulation/v1`, see [ocean-circulation-v1.schema.json](ocean-circulation-v1.schema.json) and [ocean-circulation-model.md](ocean-circulation-model.md)). Its frames are forecast/v1 frames holding the surface-temperature target and the equivalent 10 m wind; the block holds the water mask and sponge, per-frame currents, thickness, salinity (bulk and surface), temperature, sinking, fronts and stream ids, the stream and exchange-point lists, and the volume/salt budgets (`volume = initial + cumulative river + net precipitation + sponge`). The viewer validates all of it before enabling the Ocean streams view. The committed fixture `viewer/public/ocean/engine-timeline.json` is the CLI output of `examples/atlantic-streams-request.json` stored minified.

## Catchment hydrology extension

A timeline written by `terraflux-run-catchment-hydrology` carries `terrain` and a `hydrology` member (schema `terraflux.hydrology.catchment/v1`, see [catchment-hydrology-v1.schema.json](catchment-hydrology-v1.schema.json) and [catchment-hydrology-model.md](catchment-hydrology-model.md)). Its frames are ordinary forecast/v1 frames holding the forcing air temperature and zero wind; the block holds the static drainage network, per-frame stores, discharge and hazard arrays aligned with the frames, lake levels, cumulative budget totals and landslide events. The viewer validates the network (receivers, basins, lakes), every array and the water budget (`stores + ET + ocean + edge − precipitation = initial_storage_m3`) before enabling the Catchment and Hazards views. The committed fixture `viewer/public/flood/engine-timeline.json` is the CLI output of `examples/alpine-flood-request.json` stored minified.

## Coupled atmosphere extension

A timeline written by `terraflux-run-coupled-wind` carries a `coupled_atmosphere` member (schema `terraflux.weather.coupled_atmosphere/v1`, see [coupled-atmosphere-v1.schema.json](coupled-atmosphere-v1.schema.json)). Its frames are ordinary forecast/v1 snapshots with evolving wind. The extension adds the static pressure and Coriolis fields, per-frame specific humidity, relative humidity, diagnosed air density, supersaturated-cell counts and scalar stability numbers, the echoed run request and input provenance. The viewer validates array sizes, finiteness and ranges, enables the pressure, relative humidity, air density and specific humidity layers, and fills the request editor from the echoed request. An optional `columns` block (`terraflux.weather.column_diagnostics/v1`) adds per-cell, per-frame LCL, LFC, EL, CAPE, CIN, potential class and condensed water with null for missing levels; it enables the CAPE, cloud base and equilibrium-level layers. An optional `clouds` block ([cloud-formation-v1.schema.json](cloud-formation-v1.schema.json)) carries per-frame cloud genus, mechanism, trigger, base, top, fraction, thunderstorm flags and the front analysis; `source_kind` may be `engine_output` or `synthetic`, and the viewer labels synthetic data throughout. An optional `precipitation` block ([precipitation-outcomes-v1.schema.json](precipitation-outcomes-v1.schema.json), requiring `clouds`) carries per-frame precipitation type, phase, character, intensity, rate, duration, accumulation, hail, lightning, virga, wet-bulb, freezing level, precipitable water and hazards; it enables the precipitation layers of the field explorer and the weather map. Optional `surface`, `storms` ([storm-systems-v1.schema.json](storm-systems-v1.schema.json), requiring `surface`) and `severe` ([severe-convection-v1.schema.json](severe-convection-v1.schema.json), requiring `clouds`) blocks carry land/sea and sea-surface temperature, tracked tropical cyclones with their events and fields, and tornado potential. An optional `orography` block ([orography-v1.schema.json](orography-v1.schema.json), requiring the top-level `terrain`) carries per-frame orographic lifting, Froude blocking, ridge orientation, valley depth, cold pools, foehn and orographic precipitation. A timeline cannot carry both `coupled_atmosphere` and the synthetic `atmosphere` display.

Generate both bundled examples with `python3 tools/build_viewer_example.py --build-dir build`; append `--check` to verify regeneration without rewriting outputs. Production C++ kernels generate every temperature snapshot from the same initial state using successive 20-step segments. Seven synthetic reflectivity frames are independently converted to rates. The controlled scenario then appends explicit zero-rate frames from 13:10 through 14:10 UTC, producing a ten-minute linear taper followed by an hour without rain. Source derivation records this manual forcing edit. Each chronological prefix is accumulated, gridded and composed into its matching positive-time forecast. Temperature and rainfall remain independent model paths.
